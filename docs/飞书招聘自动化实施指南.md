# HireMS 飞书招聘自动化实施指南

## 已实现的工作流

```text
飞书企业邮箱（IMAP）
  → 扫描简历主题的 PDF / DOCX / TXT / MD 附件
  → 附件指纹去重、文本解析、LLM 结构化
  → 原有规则初筛 + AI 综合评分
  → HR 在本地 Web UI 复核
  → 达到阈值的候选人批量写入飞书多维表格
  → 在多维表格配置自动化：通知对应 HR / 发送候选人卡片
```

本地运行日志及邮件附件指纹位于 `data/hirems_ops.sqlite3`。该库不保存邮箱密码和简历正文；密码、飞书 App Secret 只从 `.env` 读取，绝不通过页面回显或保存。

## 一次性准备

1. 在飞书开放平台创建**企业自建应用**，由管理员开通应用可访问多维表格的权限。将应用加入目标多维表格并授予编辑权限。
2. 在目标多维表格中新建字段，名称需与下列字段保持一致：`姓名`、`邮箱`、`电话`、`岗位`、`匹配度`、`技能`、`期望地点`、`AI分析`、`处理状态`。其中“匹配度”建议用数字字段，其余使用文本/多行文本；“处理状态”建议建单选并包含“待复核”。
3. 在飞书邮箱（或企业邮箱）侧由管理员开通 IMAP/第三方客户端访问，并生成专用应用密码。不要使用员工登录密码。
4. 将 `.env.example` 复制为 `.env`，填入邮箱和飞书凭证；重启应用。`.env` 不应纳入 Git。

示例：

```env
MAIL_IMAP_HOST=imap.feishu.cn
MAIL_IMAP_PORT=993
MAIL_IMAP_USER=hr@example.com
MAIL_IMAP_PASSWORD=邮箱专用应用密码
MAIL_IMAP_FOLDER=INBOX
MAIL_SUBJECT_KEYWORDS=简历,应聘,求职

FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_BITABLE_APP_TOKEN=app_xxx
FEISHU_BITABLE_TABLE_ID=tbl_xxx
FEISHU_EXPORT_MIN_SCORE=0.70
```

> 若贵司飞书邮箱未开放 IMAP，则保持本系统的附件导入和筛选层不变，只需将 `ImapResumeIntake` 更换为贵司已获批的邮件 API 适配器。不要通过浏览器自动化或个人 Cookie 抓取邮件。

飞书多维表格写入使用批量新增记录接口；调用身份需具备该表格的编辑权限，单次最多写入 1,000 条。详见飞书官方 [批量新增记录文档](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/batch_create?lang=zh-CN)。

## 日常操作

1. 双击 `启动HireMS.bat`（已打包时会启动 `dist/HireMS.exe`），浏览器会打开本地控制台。
2. 点击“立即同步”将近期邮件附件导入简历库；重复邮件会被跳过。
3. 输入岗位要求并运行筛选。建议先把学历、教资、地区等不可妥协的条件写明。
4. 查看匹配结果后，点击“写入飞书多维表格”。只有分数不低于 `FEISHU_EXPORT_MIN_SCORE` 的候选人会被导出。
5. 在飞书多维表格中用“自动化”按“处理状态=待复核”或“匹配度≥阈值”通知岗位 HR；最终约面决定仍由 HR 做出。

## 模块 6：消息卡片与提醒

系统会在候选人首次通过筛选、进入本地待复核队列时，向 `FEISHU_HR_RECEIVER_IDS` 中的 HR 发送飞书互动卡片。卡片包含摘要、匹配分、技能及 **通过 / 淘汰 / 安排面试** 按钮；点击后状态会直接回写 HireMS。

在飞书开放平台为自建应用开启机器人能力，订阅 `card.action.trigger`，并将回调地址指向：

```text
https://你的公网域名/api/v1/feishu/card-actions
```

回调 Token 写入 `FEISHU_CALLBACK_TOKEN`。本地 `localhost` 无法被飞书回调访问；开发期可以使用飞书长连接，或通过公司批准的公网网关暴露该地址。卡片回传要求服务端快速返回成功响应，系统接口会返回操作提示并立即更新状态。

服务启动后自动安排：每天 09:00 发送昨日处理汇总、每 30 分钟检查超过 `NOTIFY_OVERDUE_HOURS`（默认 48 小时）未复核的候选人、每 5 分钟检查一小时内开始的面试并提醒面试官。工作台也提供“发送每日汇总”和“检查超时简历”的手动触发按钮。

## 模块 7：面试与 Offer 管理

候选人队列支持一面、二面、终面排期及面试评价。填写“通过”会将候选人推进到 `Offer待发`，随后依次可标记为 `Offer已发 / Offer已接受 / Offer已拒绝`。

如配置 `FEISHU_CALENDAR_ID`，系统会调用飞书日历创建日程并设置 60 分钟提醒；排期前先检查 HireMS 内已有面试冲突。若还配置 `FEISHU_INTERVIEWER_CALENDAR_MAP`（面试官 Open ID 到已授权日历 ID 的 JSON 映射），系统会进一步查询对应飞书日历，发现忙碌时拒绝该时段。应用不能在没有授权的情况下读取员工个人日历，因此该显式映射是必需的。未配置日历时，排期仍会保存在本地工作流中，便于先跑通 HR 流程。

当前版本通过面试官 Open ID 向内部人员发飞书提醒。外部候选人通常没有企业飞书 Open ID，候选人的提醒需另接企业邮件或短信服务；日程说明中会保留候选人邮箱，供 HR 用既有渠道发送邀请。

需要新增的飞书权限至少包括：机器人发消息、创建日程、读取日历忙闲信息、编辑多维表格。飞书官方对 [发送消息卡片](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create)、[卡片回传交互](https://open.feishu.cn/document/feishu-cards/card-callback-communication?lang=zh-CN) 和 [创建日程](https://open.feishu.cn/document/server-docs/calendar-v4/calendar-event/create?lang=zh-CN) 有对应说明。

## 生成 EXE

在安装 Python 的构建机执行：

```powershell
cd HireMS
.\build_windows_exe.ps1
```

生成物为 `dist/HireMS.exe`。将其与同目录的 `.env` 放在同一文件夹后运行。首次启动会在程序工作目录创建 `data/`、`cache/`、`chroma_db/` 等本地数据目录。

## 上线前检查

- 用 20–50 份已知结果的历史简历，分别验证“合适 / 待观察 / 不合适”的召回率与误杀率，再调整岗位描述和导出阈值。
- 所有候选人都应保留人工复核；不要将分数直接作为淘汰决定。
- 设置数据留存期限、操作人权限和离职人员的邮箱/多维表格访问回收流程。
- 高并发或长期运行时，建议将当前进程内简历字典替换为受控数据库，并将邮箱同步改为计划任务或服务账号运行。
